# MF03 — Appointment, Waitlist and Check-In

WBVP-SE2030; canonical business reference 3.3-AI / 2026-08-14-R9. Current implementation: `origin/develop` at `444364d4b742fa08455c4acf0538baa836e9529a` (2026-10-07 audit).

## 1. Function scope

Appointment, Waitlist and Check-In. Classification: VERIFIED_FINAL_BY_USER_CONSTRAINT. Exactly five assessed functions; shared capabilities remain supporting evidence.

## 2. Actors/roles

Citizen; Admin/Center Manager for check-in mutations; Vaccinator also has queue access. UI visibility does not broaden backend method permissions.

## 3. Primary workflow

Search availability, book, reschedule or cancel; join/leave waitlist and promote eligible candidates; permitted staff check in or reverse check-in/no-show.

## 4. Key business rules

Booking retains citizen/campaign guard and eligibility checks before reserving capacity. Waitlist ordering is FIFO. Object ownership is enforced separately from role checks.

## 7. Data/persistence touchpoints

Mapped physical tables include `appointment`, `citizen_campaign_booking_guard`, `waitlist_entry`, append-only appointment/waitlist/check-in history, durable module-event consumption and the notification outbox. MF-02 session changes cross a read-port boundary and are consumed idempotently; cancellations close affected active records while schedule/center changes preserve bookings and create review notifications.
